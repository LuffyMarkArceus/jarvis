# The Input Box (Milestone 6.7a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The TUI's input box edits like a modern text field, has a `/`
commands menu, queues messages typed while Jarvis is busy, and can steer a
running turn.

**Architecture:**
* **Editing** moves to its own pure `Input` type in `tui/src/input.rs`,
  tested as tables.
* **The commands table** in `tui/src/commands.rs` feeds both `/help` and
  the menu.
* **The queue** is TUI state, one queue per session.
* **Steer** is a per-conversation inbox in the daemon, drained by
  `model_with_tools` before each model call, with a `steer` request and
  used/unused ids in the `ask` replies.

**Tech Stack:** Rust, ratatui 0.28, crossterm 0.28 (keyboard enhancement),
tokio.

**Spec:** `docs/superpowers/specs/2026-11-21-tui-input-design.md`. Its
"Settled after the builder check" calls are requirements.

## Global Constraints

* **Words:** a word is a run of alphanumeric chars (`char::is_alphanumeric`);
  everything else separates words.
* **Ctrl+H** deletes a word back; help is F1 only.
* **Ctrl+C** cancels a turn. Esc never does.
* **Copy, verbatim:**
  * "Queue held: /resume sends it, Alt+Up edits the last one."
  * "steered: <first 40 chars>"
* **`[tui] follow_up`:** `"queue"` (default) or `"steer"`.
* **IPC:**
  * `steer {session, id, text}` → `{status: "steering"}` or
    `{status: "not_running"}`;
  * the `ask` result gains `unused_steers: [{id, text}]` on an answer, and
    `used_steers: [id]` on `{cancelled: true}`.
* **Tests:** none touches the owner's daemon, data, GPU or `~`.
* **Before every commit:** `cargo fmt`, then
  `cargo clippy --workspace --all-targets -- -D warnings` must be clean.

## Review Focus

1. **Ctrl+→ on unicode and punctuation runs:** `héllo, wörld` steps
   `héllo` → `wörld`; no panic on a cursor at the end (Task 1).
2. **Up in a multi-line message on the first line** goes to history; on a
   later line it moves up and keeps the column, clamped (Task 1).
3. **A daemon disconnect mid-turn with two queued messages and one steer
   in flight:** three items held, in order steer first, nothing sent
   (Task 5).
4. **`/resume` after switching conversations** sends only that
   conversation's queue (Task 3).
5. **A steer arriving while the model gives its final answer:** the loop
   runs one more round with it, if rounds remain (Task 4).

### Task 3: The queue

**Files:**
- Modify: `tui/src/app.rs` (queue state, `submit` while busy, turn end,
  cancel/disconnect, `/resume`, `/queue`, Alt+Up), `tui/src/ui.rs`
  (queued entries at the end of the transcript; "queued: N" in the hint)

**Interfaces (produces):**
- `pub struct Queued { pub id: Uuid, pub text: String, pub steer: bool }`.
  `steer` means it was a steer that came back.
- `App.queues: HashMap<String, VecDeque<Queued>>`, keyed by session id.
- `App.held: HashSet<String>`: the sessions whose queue is held.
- `fn queue(&self) -> Option<&VecDeque<Queued>>`: the current session's.
- **Sending a queued message** goes through the same path as a typed
  message (history, user entry, `ask`).
- **Commands** `/resume` and `/queue`.

Rules:
- **While a turn is pending,** Enter on a non-command message with
  follow_up `"queue"` pushes it to the back of the current session's
  queue.
- **When the turn's response is ok and not cancelled,** and the session
  is not held, pop the front and send it.
- **A cancelled response, an error response, or `on_disconnected`**
  marks the session held and notes the "Queue held…" line.
- **`/resume`** clears held and sends the front if no turn is pending.
- **Alt+Up** with an empty input pops the back into the input.
- **While busy:** `/resume`, `/queue`, `/steer` and Alt+Up work; other
  commands are refused as today.

- [ ] **Step 1: Write failing tests:**
  - `enter_while_busy_queues_instead_of_refusing`;
  - `the_queue_is_sent_in_order_after_each_turn`;
  - `a_cancel_holds_the_queue_and_resume_sends_it`;
  - `an_error_or_disconnect_holds_the_queue`;
  - `alt_up_takes_the_newest_back_to_edit`;
  - `the_queue_belongs_to_its_conversation` (Review Focus 4): queue in

### Task 4: Steer in the daemon

**Files:**
- Modify:
  * `core/src/conversation.rs`: `steers: Mutex<Vec<Steer>>` and
    `steerable: AtomicBool`.
  * `core/src/orchestrator/turn.rs`: drain before each model call after
    the first, and continue past a final answer while steers wait.
  * `core/src/orchestrator/outcome.rs`: `used_steers` on the recorder.
  * `core/src/orchestrator/mod.rs`: return unused steers.
  * `core/src/daemon.rs`: `steer()`, plus auto-title by "no title yet".
  * `core/src/ipc/server.rs`: the `steer` request, and the ids in the
    `ask` replies.
  * `core/src/memory.rs`: `session_title(id) -> Result<Option<String>>` if
    missing.
- Test: `core/tests/steer.rs` (the `Gated` model from `tests/common`).

**Interfaces (produces):**
- `pub struct Steer { pub id: String, pub text: String }`, in
  `conversation.rs`.
- `Conversation::steer(&self, s: Steer) -> bool`: false (and not kept)
  unless `steerable`.
- `Conversation::take_steers(&self) -> Vec<Steer>`.
- `model_with_tools`:
  - sets `steerable` true at entry and false on every exit (a guard);
  - before each model call after the first, it drains the steers. Each
    one becomes `ChatMessage::text("user", text)` labelled
    `Origin::User`, is persisted with `add_labeled_message`, is reported
    as "steered: <40 chars>", and its id is recorded in
    `rec.used_steers`;
  - when the model returns a final answer and steers are waiting with
    rounds left, the loop pushes the answer as an assistant message and
    continues, rather than returning.
- After the turn: the leftover `take_steers()` go to `TurnReport`
  (`unused_steers: Vec<Steer>`), and `used_steers: Vec<String>` is filled
  from the recorder.
- `Daemon::steer(session, id, text) -> Result<bool>`.
- **IPC `steer`:**
  - `{status: "steering"}` if the conversation accepted it;
  - `{status: "not_running"}` otherwise;
  - an error without `session`.
- **The `ask` results:** an answer adds `"unused_steers": [{id, text}]`;
  a cancel adds `"used_steers": [ids]`.
- **Auto-title** runs when the session has no title and has an answer,
  not on `count == 2`.

### Task 5: Steer in the TUI

**Files:**
- Modify:
  * `core/src/config.rs`: `TuiConfig { follow_up: FollowUp }` under
    `[tui]`, with `FollowUp { Queue, Steer }`.
  * `tui/src/app.rs`: `/steer`, Ctrl+Enter, in-flight tracking,
    `steer_pending`, re-queue rules.
  * `tui/src/main.rs`: passes `follow_up`.

**Interfaces:**
- **Consumes:** `Queued` and the queues (Task 3); the IPC `steer` and the
  `ask` reply fields (Task 4).
- **Produces:**
  - `App.follow_up: FollowUp`;
  - `App.in_flight: Vec<Queued>`, the steers sent this turn;
  - `App.steer_pending: Option<Uuid>`: the steer request's id, whose
    response `on_response` handles apart from the turn's `pending_id`.

Rules:
- **What sends a steer:** `/steer <text>`, or Enter while busy when
  `follow_up = Steer`. Ctrl+Enter (enhanced only) flips the follow-up for
  that message.
  - It sends `steer {id: uuid, text}`, adds a dim "steering: <text>"
    entry, and pushes to `in_flight`.
  - With no turn running, `/steer` sends it as a normal message.
- **`not_running`** moves that steer to the back of the queue.
- **When the turn answers:** its `unused_steers` go to the front of the
  session's queue, in order, and are sent after the turn like any queued
  message. `in_flight` is cleared.
- **When the turn is cancelled:** the in-flight steers not in
  `used_steers` go to the front of the queue, held.
- **On an error or a disconnect:** all in-flight steers go to the front,
  held.

- [ ] **Step 1: Write failing tests:**
  - `slash_steer_sends_a_steer_request`;
  - `follow_up_steer_makes_enter_steer`;
  - `ctrl_enter_flips_follow_up` (CONTROL + Enter);
  - `not_running_queues_the_steer`;
  - `unused_steers_go_to_the_front_and_are_sent_next`;
  - `a_cancel_requeues_only_unused_steers_held`;
  - `a_disconnect_requeues_every_in_flight_steer_first` (Review Focus 3):
    two queued plus one in flight gives the order steer, q1, q2, held;
  - in `config.rs`, `tui_follow_up_defaults_to_queue`.
- [ ] **Step 2:** Run `cargo test -p jarvis-tui -p jarvis-core --lib
