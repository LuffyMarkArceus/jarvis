# Modes (Milestone 6.6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each conversation has an autonomy (Plan / Interactive /
Autopilot), an approval (Manual / Assisted / Allow all) and a sandbox
toggle. One pure decision function turns your rules and the mode into run,
run read-only, ask, defer or refuse, and the protections are checked before
any mode.

**Architecture:**
* `core/src/modes.rs` holds the mode types and `decide()`. It does no I/O
  and is tested as a table.
* The gate (`gate_and_run`) asks `decide` and carries out the decision:
  * `RunReadOnly` runs `shell.run` in a sandbox with every writable folder
    read-only;
  * `Defer` records the call for `/approve`.
* Modes live on the `Conversation` and in `sessions`, and a turn pins the
  mode it started with.

**Tech Stack:** Rust, tokio, bubblewrap, rusqlite (additive migrations),
ratatui.

**Spec:** `docs/superpowers/specs/2026-11-20-modes-design.md`. Its
"Settled after the builder check" calls are requirements.

## Global Constraints

* **Defaults** (`[modes]`): `autonomy = "interactive"`,
  `approval = "manual"`, `sandbox = true`, `autopilot_rounds = 24`.
  * Serde names: `plan|interactive|autopilot` and
    `manual|assisted|allow_all`.
* **Order inside `decide`:**
  1. deny → `Refuse`;
  2. outside the sandbox after untrusted content → `Refuse`;
  3. outside the sandbox with `[sandbox] allow_outside = false` →
     `Refuse`;
  4. Plan and the call changes something → `Refuse`;
  5. approval transforms `Ask`;
  6. untrusted content inside the sandbox → `Ask`, whatever the approval;
  7. Autopilot: `Ask` → `Defer`.
* **Copy, verbatim:**
  * Plan refusal: "Plan mode changes nothing; /go to carry out the plan."
  * Read-only failure: "This ran read-only and needs to write. Call it
    again with writes: true to ask the owner."
* **Audit outcomes:** `auto_approved_undoable`, `auto_approved_read_only`,
  `deferred`, `refused_plan`, `approved_deferred`.
* **Signals:** `deferred` and `plan_refused`.
* **Autopilot never prompts.** Any confirmation reaching a confirmer during
  an Autopilot turn is answered no, and is reported.
* **Egress prompts** (`egress.send`, `egress.web`, `egress.local`,
  `egress.spill`) are not approvals. No approval mode skips them; in
  Autopilot they are answered no and reported.
* **Tests:** none touches the owner's daemon, data, GPU or `~`. Tests
  needing bwrap skip via `common::sandbox_or_skip()`.
* **Before every commit:** `cargo fmt`, then
  `cargo clippy --workspace --all-targets -- -D warnings` must be clean.

## Review Focus

1. **A model sets `writes: false`** (or omits it) on a command that writes,
   in Assisted. It runs read-only, the write fails, and the model is told
   to ask. Nothing is written (Task 3).
2. **Switching mode while a turn runs** (another window, or `/mode`
   mid-turn). The running turn keeps its mode, and the next turn uses the
   new one (Task 2).
3. **A typed "delete notes.md" in Autopilot.** It is deferred, with no
   prompt; `/approve all` deletes it, with an undo copy (Task 4).
4. **`/approve` after switching to Plan.** It refuses the deferred writes,
   and they stay listed (Task 4).
5. **Allow all with the sandbox off, after a web page was read.** A shell
   command is refused, not run (Task 3).

### Task 1: Mode types and `decide`

**Files:**
- Create: `core/src/modes.rs` (register in `core/src/lib.rs`)
- Modify: `core/src/config.rs` (`ModesConfig` under `[modes]`)

**Interfaces (produces):**
- `pub enum Autonomy { Plan, Interactive, Autopilot }`
- `pub enum Approval { Manual, Assisted, AllowAll }`
- Both: `Copy, Eq, Serialize, Deserialize, Default`.
- `pub struct Mode { pub autonomy: Autonomy, pub approval: Approval, pub sandbox: bool }`
  - `Mode::from_config(&ModesConfig) -> Mode`
  - `fn label(&self) -> String`, for example "Interactive · Assisted · Sandbox on"
  - `fn within(&self, ceiling: &Mode) -> Mode`: clamps approval
    (Manual < Assisted < AllowAll) and sandbox (on < off); never changes
    autonomy.
- `pub enum Change { None, Undoable, NotUndoable, Shell { writes: bool }, Outside }`:
  what a call does.
  - `Outside` covers outside the sandbox and app launches.
  - `None` covers reads, search, process and system info, and web calls.
- `pub struct Call { pub rule: PermissionAction, pub change: Change, pub untrusted: bool, pub allow_outside: bool, pub sandbox_ready: bool }`
- `pub enum Decision { Run, RunReadOnly, Ask, Defer(String), Refuse(String) }`
- `pub fn decide(mode: &Mode, call: &Call) -> Decision`

Key rules, from the spec:
- **Assisted:**
  - `Ask` with `Undoable` → `Run`;
  - `Ask` with `Shell { writes: false }`, when `sandbox_ready` and
    `mode.sandbox` → `RunReadOnly`;
  - everything else stays `Ask`.
- **Allow all:** `Ask` → `Run`, except where untrusted content applies
  (rule 6).
- **A rule of `Allow`:** stays `Run`, and Plan still refuses changes.
- **Untrusted content:** `Allow` becomes `Ask` too, so rule 6 applies to
  any verdict that is not deny.

- [ ] **Step 1: Write failing table tests** in `modes.rs`:
  - `protections_hold_in_every_mode`: iterate every autonomy × approval ×
    sandbox.
    - `rule = Deny` → `Refuse` always.
    - `Outside` with `untrusted` → `Refuse`.
    - `Outside` with `!allow_outside` → `Refuse`.
    - `untrusted` with `Undoable`, under `AllowAll` → not `Run`: `Ask`, or
      `Defer` in Autopilot.
  - `plan_refuses_every_change_and_runs_reads`: Plan with `Undoable`,
    `Shell { writes: true }` or `Outside` → `Refuse(...)` containing "Plan
    mode changes nothing". `None` with `Allow` → `Run`. `Shell
    { writes: false }` with a ready sandbox → `RunReadOnly`.
  - `assisted_runs_what_can_be_undone_or_only_reads`:
    - `Ask` with `Undoable` → `Run`;
    - `Ask` with `NotUndoable` → `Ask`;
    - `Ask` with `Shell { writes: false }` → `RunReadOnly`;
    - `Ask` with `Shell { writes: true }` → `Ask`;
    - `Ask` with `Outside` → `Ask`;
    - with `sandbox_ready: false`, `Shell { writes: false }` → `Ask`.
  - `allow_all_runs_asks_but_not_after_untrusted`.
  - `manual_keeps_rules_as_written`.

- Test: `core/tests/modes_gate.rs` (new); unit tests in `undo.rs` and

**Interfaces:**
- **Consumes:** `decide`, `Mode` and `Call` (Task 1), and `rec.pinned.mode`
  (Task 2).
- **Produces:**
  - `Orchestrator::change_of(name, args) -> Change`:
    - `filesystem.write`, `edit` and `delete` → `Undoable` if
      `undo.can_keep(path)`, else `NotUndoable`;
    - `shell.run` → `Outside` if `runs_outside(...)`, else `Shell { writes }`;

  - On `Run` after an approval that skipped a prompt, the audit outcome is
    `auto_approved_undoable` or `auto_approved_read_only`.
  - If the undo copy then fails (the existing `warn!` path) on an
    auto-approved write, the write is not made, and the outcome says "no
    undo copy could be kept, so it was not written automatically".

### Task 4: Autopilot: defer, never prompt, `/approve`

**Files:**
- Modify:
  * `core/src/conversation.rs`: `deferred: Mutex<Vec<Deferred>>`.
  * `core/src/orchestrator/execute.rs`: `Defer` records the call.
  * `core/src/orchestrator/mod.rs`: in an Autopilot turn the confirmer is
    wrapped by `NoPrompts`, which answers no and records what it refused.
    The round budget is `autopilot_rounds`. The answer is followed by the
    report.
  * `core/src/orchestrator/prompt.rs`: the Autopilot and Interactive
    prompt lines.
  * `core/src/daemon.rs` and `ipc/server.rs`: `approve`.
  * `core/src/orchestrator/turnlog.rs`: the `deferred` signal.
- Test: `core/tests/modes_gate.rs`.

**Interfaces (produces):**
- `pub struct Deferred { pub name: String, pub args: Value, pub why: String, pub untrusted: Vec<Source> }`
- `Orchestrator::approve(&self, conv, which: Approve) -> Result<String>`,
  where `pub enum Approve { List, All, One(usize), None }`.
  - Each item runs through `decide` with the conversation's current mode,
    with `rule` forced to `Allow` (the owner said yes) but the protections
    and Plan kept.
  - It is audited `approved_deferred`.
  - It returns a text summary.
- IPC `approve {session, which: "list"|"all"|"none"|<n>}` →
  `{text, remaining}`.
- The list is cleared at the start of the next `run_turn` on the
  conversation.
- **The report**, appended to an Autopilot answer when anything was
  deferred or refused:
  "Waiting for you (/approve all, /approve <n>, /approve none):\n1. <describe_step>…",
  plus "Not done: <egress refusals>".
- **Prompt lines:**
  - Interactive: "If the request is ambiguous, ask one short question
    instead of guessing."
  - Autopilot: "You are on Autopilot: do not ask questions; choose
    sensible defaults, say what you assumed, and carry the task to the
    end."
